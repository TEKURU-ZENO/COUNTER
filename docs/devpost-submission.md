# COUNTER: submission write-up

## Problem

Independent takeaways lose money to phone orders that are never collected, and the phone interrupts the
kitchen at the busiest time. Many of these shops don't use an online ordering platform for their phone
customers.

*Industry figures for no-show rates and costs are not cited here; add sourced numbers before submitting,
or leave this section qualitative.*

## What COUNTER does

A caller orders by voice. The agent prices the order, reads it back, and texts a PayPal link (or, for a
returning caller who opted in, charges their saved PayPal after an SMS code and a recorded spoken "yes").
The kitchen only sees an order after PayPal confirms the capture and the amount matches the quote.

## How it is built

- **LLM tool calling with typed arguments.** The model chooses tools; Pydantic validates every argument;
  invalid arguments make the agent ask the caller rather than guess.
- **Deterministic guard and state machine** decide what may happen; the model has no tool that sets a price,
  a discount or a refund amount, and no tool that charges a wallet.
- **PayPal** Orders v2 (itemised, vault on success, vault charge), Payments v2 refunds, webhook verification,
  Transaction Search. Every capture is reconciled against the quote.
- **Transactional outbox → Redis → SSE** keeps kitchen, console and customer pages live across processes.
- Python (FastAPI, SQLAlchemy), Next.js 15, Postgres, Redis, Render.

## AI and tools disclosure

- Agent LLM in the demo: `openai/gpt-oss-120b` via Groq (OpenAI-compatible API); `qwen/qwen3.8-27b` compared in
  the evaluation; `openai/gpt-oss-20b` as the simulated caller. Anthropic models are supported but were not used in the recorded demo.
- Menu photo extraction: Anthropic vision model (requires an Anthropic key; not exercised in the demo unless configured).
- Speech in the web demo: the browser's Web Speech API. Phone channel: Twilio speech recognition and `<Say>`.
- Code was written with the help of Claude Code (Anthropic).
